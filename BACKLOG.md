## 🔴 High Priority (Immediate Fixes & Core Content)

- [ ] **Payment gateway. Next iteration, and nothing is broken today.** Membership is sold today by a request-and-reply flow: `/membership` sends the reader to `/contact`, the message is validated and stored by `netlify/functions/contact.ts`, and a link is sent back by hand. **That flow works and is not to be dismantled until a gateway replaces it.** What exists in the repo, recorded here so nobody re-derives it: `STRIPE_PAYMENT_LINK` is defined in `src/data/membershipData.ts` and is **wired to nothing**; no component imports it, no checkout is designed, and the URL it holds predates the current offer and should be treated as unverified. The published price is a single constant, `MEMBERSHIP_PRICE_STANDARD`. A second, lower price exists as a warm-lead price sent by email to a selected list; it is **not public**, it is deliberately not a constant, not a tier and not rendered anywhere, and the header comment in `membershipData.ts` is its only record in this repo. Any gateway work must keep it that way: one published price on the site, the other in email only. Spec: [`openspec/specs/membership-page`](openspec/specs/membership-page/spec.md), which needs a delta before a gateway is built.
- [ ] **The venue contradiction is real, but the recorded cause and cure were both wrong. Fix it in Luma.** The live feed says `Capital Factory, 701 Brazos St` while every other surface says Station Austin. What was previously recorded here — that the Postgres `events` table holds stale rows and that `db/migrations/02_event_venue_station_austin.sql` plus `scripts/fix-event-venue.mjs` will fix them — **does not describe the running system**. Verified 2026-08-27 by fetching `https://ifn.community/api/events` and comparing it to `git show origin/main:src/data/events.json`: the two are **byte-identical after JSON parse**, which is only reachable through the zero-rows fallback branch in `netlify/functions/events.ts`. The `events` table is therefore **empty**, the migration has nothing to operate on, and running it would report success while changing nothing. The actual source is Luma: `.github/workflows/sync-events.yml` runs on the 1st and 15th, `scripts/update-events.js` writes `location_name` from `geo_address_info.full_address`, and Luma's records still say Capital Factory — which is why the hand-edit to `src/data/events.json` on the redesign branch kept being reverted. A hand-edit cannot survive a generator. `scripts/update-events.js` now rewrites the two known-stale strings on the way in as a **stopgap**; the fix is to correct the venue on the Luma event records, then delete `KNOWN_STALE_VENUES` from that script. Spec + known gap: [`openspec/specs/events-hub`](openspec/specs/events-hub/spec.md).
- [ ] **`Event` JSON-LD is withheld until the Luma venue is fixed, and should be added the same day it is.** It is the highest-value structured-data type available to an events-driven site and it is deliberately absent from `src/data/structuredData.ts`, which explains why in its header comment. Marking up a venue that contradicts the rendered page is a Google structured-data policy violation, and generating it from `src/data/events.json` would additionally hand the machine-readable venue to a third-party calendar that reverts it twice a month. Blocked strictly by the item above; nothing else is in the way.
- [ ] **Mentorship landing page**: build out from placeholder to a conversion-focused page for mentors. Spec: [`openspec/specs/placeholder-pages`](openspec/specs/placeholder-pages/spec.md).
- [ ] **Investor pipeline**: initial data gathered in [VC_BACKLOG.md](VC_BACKLOG.md). Future: a dedicated investor-facing section or page (no spec yet, write one via `/opsx:propose` before starting).
- [ ] **The three public POST endpoints have no abuse control of any kind.** `/api/contact`, `/api/join` and `/api/event-signup` accept unlimited submissions: no rate limit, no captcha, no honeypot, no origin check. Verified 2026-08-27 by grepping `netlify/functions/` for every common mechanism — nothing matched. Each writes a row to Postgres, so this is a data-quality problem and a cost problem at the same time, and it lands on the one table that **is** the membership funnel until a payment gateway exists (see the contact-notification item below). Cheapest credible fix that does not add a vendor or a visible obstacle: a honeypot field the browser hides and a human never fills, plus a per-IP counter in the function. Netlify's own rate limiting is an alternative but is a paid-plan feature. Whichever is chosen needs a spec first — this touches three capabilities at once (`join-flow`, `contact-flow`, `events-hub`).
- [ ] **`join.ts` has no server-side validation**, unlike `contact.ts`/`event-signup.ts`. Spec + known gap: [`openspec/specs/join-flow`](openspec/specs/join-flow/spec.md).
- [ ] **Contact form outbound notification**: messages are validated and stored (working), but nothing forwards them to an inbox yet. Spec: [`openspec/specs/contact-flow`](openspec/specs/contact-flow/spec.md). This is load-bearing for the item above it: until a payment gateway exists, this inbox **is** the membership funnel.
- [ ] **`About.tsx`'s "Apply to Join" button has no click handler**, a dead button in production. Spec + known gap: [`openspec/specs/legal-static-pages`](openspec/specs/legal-static-pages/spec.md).

Run the proper cycle over both when the payment gateway and the partner artwork land.
- [ ] **`/gallery` shipped without a capability spec.** The route, its lightbox and the photo build pipeline (`scripts/photos.manifest.json` plus `scripts/build-photos.mjs`) landed in the 2026-08-10 redesign round. Behaviour is documented in `REDESIGN-PLAN.md` section 7 and `DESIGN.md`, but neither is an OpenSpec capability spec, and `AGENTS.md` asks for one. Write it via `/opsx:propose` and retro-file it beside `home-page`.
- [x] **Resource Hub Redesign (Phase 1)**: page shell shipped with all audiences, stages, and resource cards. Spec: [`openspec/specs/resources-hub`](openspec/specs/resources-hub/spec.md).
- [ ] **Resource Hub Content (Phase 2, Month 1-2)**: US Market Entry section first, highest value content.

- [ ] **Resource Hub Content (Phase 4, Month 4-6)**: SMB section and video content across all sections.
- [ ] **Loading Optimization**: reduce "Loading..." flicker between routes. **Narrowed by the 2026-08-27 prerender work, not solved.** A cold load of any of the eleven indexable routes now paints real prerendered HTML immediately, so the flicker is gone on first paint. It remains on **client-side navigation between routes**, which is still `React.lazy` behind a Suspense fallback that renders the literal string "Loading…" (`PageFallback` in `src/App.tsx`). Worth knowing before touching it: `scripts/prerender.mjs` keys its readiness check on that fallback disappearing, so renaming or restructuring it will break the build's snapshot detection — see the `waitForRender` note in that file.
- [ ] **A cold deep link to a below-fold home anchor silently does nothing.** `src/components/ScrollToAnchor.tsx` calls `document.getElementById` once, synchronously, in an effect keyed on the hash. The four below-fold anchors on `/` (`#events`, `#partners`, `#resources`, `#faq`) belong to lazily loaded sections, so on a cold load of `https://ifn.community/#events` the element does not exist yet, the guard falls through and no scroll ever happens. Verified in a headless browser at 1, 2.5 and 5 seconds: `scrollY` stays at 0. Setting the same hash **after** the page has loaded works correctly and lands the section at 72px, which is the `scroll-margin-top: 4.5rem` clearing the 65px bar, so the anchor contract itself is sound and only the cold path is broken. Predates the redesign and is untouched by it. Fix is a retry or a `MutationObserver`, not a longer `setTimeout`. Spec: [`openspec/specs/home-page`](openspec/specs/home-page/spec.md).
- [ ] **Analytics is wired but dormant: it needs one environment variable.** GA4 landed 2026-08-27 (`src/lib/analytics.ts`, `src/components/Head.tsx`, `src/components/ConsentBanner.tsx`) behind Google Consent Mode v2, storage denied by default, with page views sent manually after the title updates — GA4's automatic page view fires once per session in a single-page app and would attribute every route change to the landing URL. Conversion events are emitted from the three form success states. **All of it is a no-op until `VITE_GA4_MEASUREMENT_ID` is set in Netlify** (Builds scope, Production context only), and it is a build-time variable so the site must be rebuilt after setting it. Two non-obvious steps that will otherwise cost a quarter of bad data, both in `SEO-RUNBOOK.md` §3.1: turn OFF GA4's Enhanced Measurement "page changes based on browser history events" or every page view is **counted twice**, and mark the three conversion events as key events in the GA4 admin or they never appear in conversion reports. Note also that Google Search Console is **already verified** for this domain via a DNS TXT record — nothing in this repo shows it, and a code-only audit will wrongly report it as unconfigured.
- [ ] **Content Security Policy: written, documented, deliberately NOT enabled.** `public/_headers` carries a complete starting policy, commented out, together with the sha256 hash of the one inline classic script (the theme bootstrap in `index.html`, which cannot become an external file without reintroducing the flash of the wrong palette) and the one-liner that recomputes that hash from `dist/index.html` when the script changes. It is off because a wrong CSP breaks the site silently for real visitors while passing every check anyone would think to run. Three things the policy has to keep, all easy to drop by accident and all recorded in the file: `style-src 'unsafe-inline'` because framer-motion writes inline styles on every animated element, `images.lumacdn.com` because event covers are hotlinked from Luma, and `accounts.google.com` because `/admin` sign-in is framed. Ship it as `Content-Security-Policy-Report-Only` first, watch the console on `/admin` and `/gallery` specifically, then enforce.
- [ ] **Nothing reports a production failure.** No error tracking, no uptime check, and no Netlify deploy notifications are configured. A function returning 500s is currently invisible until a person reports it, and there is no inbox that person would reach (see the contact-notification item). This matters more since 2026-08-27 than it did before: `npm run build` now ends with `scripts/prerender.mjs`, which drives headless Chrome and **fails the build by design** rather than shipping empty pages, so the build has a genuine new failure mode. Minimum viable: turn on Netlify build-failure notifications (Site configuration → Notifications). Beyond that, Sentry's free tier covers the functions.
- [ ] **Database backup posture is unconfirmed.** The Neon Postgres behind `NETLIFY_DATABASE_URL` holds the contact messages, join submissions and event signups, and those rows are the only copy of the membership funnel — there is no export, no cron dump and no second store. Neon offers point-in-time restore on some plans; confirm which plan this project is on and whether it is enabled. Not verified from this repo, because nothing here connects to the production database.
- [ ] **Chapter Map**: interactive map/list of global chapters. Spec: [`openspec/specs/placeholder-pages`](openspec/specs/placeholder-pages/spec.md).
- [ ] **Blog/Playbooks**: build out content/CMS. Spec: [`openspec/specs/placeholder-pages`](openspec/specs/placeholder-pages/spec.md).

- [ ] **Live `events` table and scraped `events.json` are never reconciled**, two independent stores. Spec + known gap: [`openspec/specs/events-hub`](openspec/specs/events-hub/spec.md). This entry used to say the venue item at the top was the first symptom of this gap reaching production. **That is no longer the right reading**: the table was found empty on 2026-08-27, so the two stores are not currently disagreeing — only one of them is in use, and the venue bug comes from Luma upstream of both. The gap is still real and still worth closing, because the moment anything writes rows to that table the deployed feed silently stops reflecting `events.json` with no signal anywhere, but it is a latent risk rather than an active symptom.

## 🟢 Low Priority (Polish & Infrastructure)

- [ ] **Auto-publishing meetup photographs to Instagram and to this site.** Named by the founder as a future workflow: photographs taken at a meetup would reach both surfaces without a manual build step. **Nothing is implemented and nothing should be until it is spec'd**, because the current pipeline is deliberately manual for two reasons that any automation has to answer. First, consent: `assets/photos-source/README.md` treats an unrecorded consent as a refusal, and the 2026-08-10 clearance covers the fifteen frames that exist, not frames that do not exist yet. Second, selection: `scripts/photos.manifest.json` carries a hand-written crop box, grade and alt text per frame, and `REDESIGN-PLAN.md` section 7 records why each unused frame is unused. An auto-publisher has to either preserve that per-frame judgment or state plainly that it is dropping it.
- [ ] **Partner artwork.** Two of the three marks on `/partners` and in the home PartnersStrip render a labelled reserved slot rather than a logo. The `google.com/s2/favicons` hotlinks that used to fill them are deleted and must not return; no substitute monogram is drawn, because a generated mark is only permissible for an invented brand. To land real artwork: drop the file into `public/partners/` and add one `logo` key to that partner in `src/data/partnersData.ts`. Two steps, zero component edits. Spec: [`openspec/specs/partners-page`](openspec/specs/partners-page/spec.md).
- [x] **SEO / AEO: unique metadata, structured data and prerendering. Shipped 2026-08-27 on `seo/aeo-analytics-and-crawlability`.** Every indexable route now has its own `<title>`, description, canonical and Open Graph block, driven by one table in `src/data/seo.ts` that also generates `sitemap.xml`, `llms.txt` and the prerender route list, so the three cannot drift from each other. `scripts/prerender.mjs` renders each route in headless Chrome at build time and writes `dist/<route>/index.html`; before this, **every URL on the domain returned the same 3.3 KB empty `<div id="root">`**, which Google renders but GPTBot, ClaudeBot, PerplexityBot, CCBot and every social unfurler do not. Structured data (`src/data/structuredData.ts`): Organization, WebSite, WebPage, BreadcrumbList, the membership Offer, and a FAQPage harvested from the rendered DOM at build time rather than kept as a second hand-written copy that would drift silently. Also fixed: the `/*` catch-all returned **200 for every nonexistent URL and every missing asset**; `robots.txt` `Disallow` and `X-Robots-Tag: noindex` were cancelling each other out on seven paths; and `robots.txt` advertised a `sitemap.xml` that did not exist and was answered by the HTML shell with a 200. See `SEO-RUNBOOK.md` and the new `AGENTS.md` section. **No capability spec was written** — same gap as `/gallery` below.
- [ ] **The SEO/AEO round shipped without a capability spec.** Same omission as `/gallery`, recorded rather than quietly skipped: the work was diagnostic (every change traces to a defect verified against the live site) and went straight to a branch, bypassing the `/opsx:propose` cycle `AGENTS.md` requires. The reasoning is preserved in the commit messages, `SEO-RUNBOOK.md` and the new `AGENTS.md` sections, which is enough to write the spec from. Retro-file it beside `home-page`, and fold in the prerender contract — a route added to `App.tsx` without a `ROUTE_SEO` entry is silently not prerendered, not sitemapped and not in `llms.txt`, and **nothing catches that automatically**.
- [ ] **The Open Graph share card is a generated stopgap, not a designed asset.** `public/og-image.png` is produced by `scripts/build-og-image.mjs` from the shipped palette and the real MuseoModerno wordmark. It replaced `public/logo.png`, which was the site's `og:image` and was in fact a **screenshot of the retired site's call to action**, containing a visible broken-image icon, a stray text-selection artefact, and four claims the current site contradicts: "Join thousands of founders", "Free to join", "No credit card required", and "Applications reviewed weekly. Next cohort opens Monday". That image was attached to every link to ifn.community ever pasted into Slack, LinkedIn, WhatsApp or iMessage. The replacement is honest and correctly sized at 1200×630, but it is tokens and type, not design. When a real card exists in the sibling `ifn-brand` repo, drop it in at the same filename; `index.html` already points there and no component changes. Per-route share images (`/gallery` and `/events` would benefit most) are a separate, larger piece of work and are **not** started.
- [ ] **Social Links**: update footer social icons with real IFN handles. `src/data/socialLinks.ts` flags the unconfirmed ones `verified: false` and they ship as live links. **This now has a second consequence beyond a possibly-wrong footer icon.** The `Organization` JSON-LD in `src/data/structuredData.ts` builds its `sameAs` array by filtering on that exact flag, so search engines are currently told about the Luma calendar and nothing else — LinkedIn and Instagram are withheld. That filter is deliberate and should stay: `sameAs` is an identity assertion, and pointing it at an account IFN may not own is how an unrelated profile gets merged into IFN's knowledge-graph entity. Confirming each handle and flipping its flag is all that is needed; no other file changes.
- [x] **Dark Mode Support**: theme toggle. Tokens swap in `src/index.css` (light on bare `:root`, dark under a `prefers-color-scheme` block guarded as `:root:not([data-theme="light"])` and again under `:root[data-theme="dark"]`). The footer control is `src/components/ThemeToggle.tsx`: three states (light, system, dark), `system` by default and stored as the absence of the `ifn-theme` key. The no-flash bootstrap is the inline classic script in `index.html`.
- [x] **Performance Optimization (Batch 1)**: lazy-loading, resized hero images, LCP preload, font-loading fixes.
- [x] **Automated Performance Audit**: `scripts/audit-performance.js`, `npm run audit`.
- [x] **Automated Testing Suite**: Vitest added, covering the validated backend functions and auth logic. Tests live in `netlify/tests/`, never inside `netlify/functions/` (see `AGENTS.md` for why that breaks the deploy). Playwright/E2E not yet added.
- [ ] **HSTS `preload` is deliberately not set, and that is a decision to revisit, not an oversight.** `public/_headers` sends `max-age=63072000; includeSubDomains` as of 2026-08-27, upgraded from the bare `max-age=31536000` the site had. `includeSubDomains` was added only after checking it was safe: `qr.ifn.community` and `www.ifn.community` are the only subdomains that resolve and both already serve HTTPS with HSTS of their own, so nothing was cut off. `preload` was left off because it is close to irreversible — removal from the browser preload list takes months to propagate — and it commits every future subdomain to HTTPS forever. Add it, and submit at `hstspreload.org`, only as a conscious decision.
- [ ] **Confirm Netlify deploy previews are `noindex`.** Netlify sends `X-Robots-Tag: noindex` on deploy previews by default, but this has not been verified for this project and an indexed preview URL competes with production for the same content — which matters more now that previews serve fully prerendered, indexable HTML rather than an empty shell. One command on the next preview: `curl -sI "$PREVIEW/" | grep -i x-robots-tag`.
- [ ] **`admin-submissions` has no pagination/limit**, fine at current volume, will need one as tables grow. Spec + known gap: [`openspec/specs/admin-dashboard`](openspec/specs/admin-dashboard/spec.md).
- [ ] **`sync-all.js` redundantly re-runs both scrapers** that the GitHub Action already ran individually. Spec + known gap: [`openspec/specs/events-hub`](openspec/specs/events-hub/spec.md).
- [x] **DECIDED 2026-08-10: `public/photos/` and `src/data/photos.generated.ts` are COMMITTED build outputs.** `npm run build` is `tsc -b && vite build` with no `photos` step, and six modules import `photos.generated` (`Hero`, `HowItWorks`, `FounderStory`, `GalleryPreview`, `Gallery` and `GalleryLightbox`), so a fresh clone typechecks only if these are committed. This was left as an open decision for one round and the round nearly shipped the bad half of it: `photos.generated.ts` was already tracked and modified while 52 of its 68 derivatives were untracked, so a routine commit would have published a tracked module referencing files that never reached the repository. Netlify builds from git, so `/gallery` would have rendered ten broken tiles in production while lint, typecheck, test, build and the contrast gate all passed locally. Nothing in the verification line catches that. The decision is therefore made in the direction the existing 16 tracked derivatives already implied: **derivatives are committed**, `sharp` stays out of the deploy path, and adding `npm run photos` to `build` is explicitly NOT done. The cost is repository weight, currently about 3.1MB of derivatives, and it is paid knowingly. Adding a photographic slot means committing its derivatives in the same commit.
